# Сервис уведомлений

Автор: Васильев Тимур Артемович

## Что делает программа

Сервис отправки уведомлений. 2 способа - email и push.

## Как запустить

go run ./cmd/notify

go test ./practice

## Проверенные случаи

Успешная отправка: в обе истории сообщений добавляется сообщение «Заказ принят».

Отправка пустого текста: Dispatch возвращает ошибку, оборачивающую ErrEmptyMessage, уже на первой итерации. Истории сообщений остаются без изменений.

Отправка через push-notifier без device ID: Dispatch возвращает ошибку, оборачивающую *SendError. Истории сообщений не изменяются.

Отправка через BrokenNotifier: SafeDispatch добавляет в возвращаемый слайс ошибку, оборачивающую ErrNotifierPanic. При этом исправный push-notifier успешно отправляет сообщение «schemotechnique» и добавляет его в свою историю.

## Обработка ошибок

Dispatch останавливается при первой ошибке и возвращает её с дополнительным контекстом. Паники эта функция не перехватывает.

SafeDispatch продолжает обработку остальных notifier, даже если один из них вернул ошибку или вызвал панику. Все ошибки собираются в слайс; паника преобразуется в ошибку, оборачивающую ErrNotifierPanic.

В main() функция errors.Is используется для проверки на ErrEmptyMessage, а errors.As — для извлечения ошибки типа *SendError.

recover вызывается непосредственно внутри отложенной функции defer: при панике обычное выполнение прерывается, а отложенные вызовы выполняются по мере раскрутки стека. Вызов recover вне этого контекста не перехватит панику.

Перехват паники организован в SafeSend, чтобы сбой одного канала не мешал отправке сообщений через остальные.
